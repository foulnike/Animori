# Безопасность

**Редакция от 9 октября 2026 года.**

## Как сообщить об уязвимости

**Не создавайте публичный Issue с описанием уязвимости.** Публичное
обсуждение живого дефекта даёт окно для его использования до выхода исправления.

Сообщите через приватный канал GitHub —
[Security Advisory](https://github.com/foulnike/Animori/security/advisories/new)
(вкладка Security → Report a vulnerability). Опишите:

- что происходит и какой ущерб возможен;
- как воспроизвести (номер версии, платформа: настольное приложение или приставка);
- если есть — набросок исправления.

Если приватный канал по какой-то причине недоступен, откройте Issue **без
подробностей эксплуатации** — только факт «нашёл проблему безопасности, готов
описать приватно» и способ связи. Мы переведём разговор в приватный канал.

## Что мы считаем уязвимостью

- исполнение кода в окне программы, обход Content Security Policy;
- утечка секретов, которые программа хранит (пропуск AniList, пропуск облака,
  пароль прокси) — через интерфейс, лог или файл настроек;
- выход за папку программы при чтении или записи файла;
- подмена сетевого адреса запроса за пределы разрешённого списка;
- исправление или подпись обновления, которое не является нашим.

## Сроки

- подтверждение получения — в течение 3 рабочих дней;
- предварительная оценка степени риска — в течение 7 дней;
- для подтверждённых уязвимостей — план исправления и ориентировочные сроки
  отдельным сообщением.

Мы придерживаемся практики **координированного раскрытия**: подробности
публикуются после выхода исправления. С согласия автора сообщения указываем его
в качестве автора находки.

## Область применения

| Продукт | Как поддерживается |
| :--- | :--- |
| Настольное приложение (Windows) | последняя версия, тег `windows-v*` |
| Приложение для телевизора (Android TV) | последняя версия, тег `android-tv-v*` |
| Мобильное приложение (Android, телефон) | последняя версия, тег `android-v*` |

Исправления уязвимостей выходят в следующий выпуск соответствующего продукта.
Отдельных патчей для старых версий мы не выпускаем: обновление — основной способ
получить исправление.

## Обновления и подпись

Настольное приложение проверяет обновления и подпись. Обновление принимается
только с верной подписью издателя; чужая или испорченная сборка отвергается.
Отключать проверку подписи мы не поддерживаем и такой возможности не даём.

Телефон и приставка отдают установку системе: APK подписывается нашим ключом
в конвейере, и установщик ставит обновление только поверх той же подписи.
Отключить эту проверку и на этих платформах нельзя.

## Модель угроз webview

Приложение построено на Tauri: интерфейс — локальная сборка в окне WebView2,
логика и доступ к системе — в Rust. Ключевое допущение защиты: **исполнение
произвольного JavaScript в окне не равно доступу к машине.** Каждое звено пути
«код в окне → хост» разорвано намеренно.

- **CSP** (`script-src 'self'`, `object-src 'none'`, `base-uri 'self'`,
  `form-action 'none'`) — нет `unsafe-eval` и `unsafe-inline` для скриптов:
  `eval`, `new Function` и подключение внешнего скрипта блокируются.
- **Окно загружает только свою сборку** (`WebviewUrl::default()` = `index.html` из
  `frontendDist`). Удалённые адреса в IPC не пущены: `withGlobalTauri: false`,
  глобального `__TAURI__` в окне нет, `dangerousRemoteDomainIpcAccess` не
  включён.
- **Плагинов shell и fs нет.** Произвольный запуск программ и чтение файлов вне
  белого списка недоступны. `tauri-plugin-opener` зарегистрирован только со
  стороны Rust, разрешение `opener:allow-open-url` окну не выдано: внешний
  адрес открывается лишь через `animori_open_external`, которая пропускает
  только `http`/`https` и отсекает `file:`, `ms-settings:` и прочее.
- **Команды IPC узкие.** Запрос к AniList не принимает мутирующие операции;
  файловые команды читают и пишут по белым спискам имён в служебном каталоге с
  записью через временный файл; закрытые ключи настроек из окна не отдаются.
- **HTTP-плагин ограничен списком хостов** (`capabilities/default.json`), а не
  шаблоном `https://*`.
- **Разметка:** `v-html` используется только на статических локальных SVG
  (`*.svg?raw`, выбор по закрытому перечислению имён), внешние и пользовательские
  данные в разметку как HTML не попадают.

Проверено по исходникам текущей версии (октябрь 2026). Это фиксация допущений, а
не гарантия: уязвимость в WebView2, в Rust-слое или в зависимостях откроет свой
путь эскалации — сообщите о ней по каналу выше.

### Телефон (apps/android)

Слои те же, что на десктопе: локальная сборка в окне WebView, CSP без
`unsafe-inline` и `unsafe-eval` для скриптов, `v-html` только на статических
локальных SVG, http-запросы по списку хостов, узкие команды IPC. Специфика:

- **JavascriptInterface.** Оболочка выдаёт странице шестнадцать примитивных
  методов (ориентация, PiP, медиа-состояние, выбор документов, обновление).
  Пропуск AniList мосту недоступен: ключи `auth_token` и `auth_expires_at`
  команда настроек окну не отдаёт.
- **Установка обновления.** Мост `install` принимает только `https`-адрес;
  APK скачивается в кеш приложения и отдаётся системному установщику,
  который сверяет подпись — обновление встаёт только поверх той же подписи.
  Разрешение `REQUEST_INSTALL_PACKAGES` дано осознанно и только под это.
- **Хранение секретов.** `animori-settings.json` лежит в песочнице приложения
  открытым текстом: на десктопе пропуск облака шифруется DPAPI, на телефоне
  нет. Бэкапы выключены (`android:allowBackup="false"`): копии секрета не
  должно ни у облака Google, ни у переноса при смене телефона.
- **Облако Яндекс Диска.** Токен уходит только заголовком `Authorization`
  по HTTPS, в адреса не попадает и в журналы не пишется. Как и на десктопе,
  страница читает его из настроек — защита от исполнения чужого кода в окне
  та же: CSP и санитайзер разметки.

### Чего это не закрывает

Исполнение кода в окне само по себе не безобидно: злоумышленник с JS может
переписать локальный снимок списка, открыть произвольный `http(s)`-адрес в
браузере через `animori_open_external` и обращаться к разрешённым хостам API с
учётными данными пользователя. Чего он **не может**: выполнить код на машине,
прочитать пропуск AniList и пропуск облака из настроек, читать файлы вне
песочницы и запускать программы. Включённая панель разработчика (`devtools`)
границ не меняет — эскалация заперта слоями выше.

## Что уязвимостью не является

- поведение, которое является свойством выбранного стороннего сервиса (смена
  формата ответа, блокировка по регионам, требования к авторизации);
- отсутствие функции, которая не входит в назначение программы;
- Findings сканеров, которые не удалось воспроизвести на реальной сборке
  без предоставления сценария эксплуатации;
- отчёты, полученные только автоматическим сканированием без ручной проверки
  и доказательства воздействия.
