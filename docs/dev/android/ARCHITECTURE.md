# Архитектура приложения для телефона

## Слои

Интерфейс — Vue 3 (`apps/android/src`), общее ядро — `packages/core` (TypeScript
без DOM), оболочка — Tauri 2 (`apps/android/src-tauri`), нативная часть —
Kotlin-активность в `src-tauri/gen/android`. Один webview, контент — сборка
`dist/app`; второго окна интерфейса нет.

## Мосты

Страница → оболочка, два канала:

- **Tauri-команды** (`capabilities/default.json`): настройки, файлы, вход,
  запросы к AniList, выгрузка, прокси. Права у окна `local` и один файл — `main`.
- **JavascriptInterface** (`MainActivity.kt`): 16 методов — ориентация и инсеты,
  Picture-in-Picture, медиа-состояние, выбор и запись документов, обновление.

Оболочка → страница: `evaluateJavascript` с именами `window.__am*`.

## Ограничения окна

- CSP: `script-src 'self'` без inline и eval, удалённый IPC не разрешён.
- `opener` и `dialog` не выданы окну: внешний адрес открывается только командой
  с проверкой схемы (http/https).
- Закрытые ключи настроек (`auth_token`, `auth_expires_at`) команда настроек
  окну не отдаёт.
- `v-html` применяется только к статическим локальным SVG.

## Picture-in-Picture и кнопки плеера

Web-PiP в Android WebView не поддержан: кадр в маленькое окно уносит активность
(мост `AnimoriPip` — рект кадра, признак игры, вход по сворачиванию).

Кнопки плеера на окне PiP (пуск/пауза, смена серий) рисует системный оверлей
Android 12+ поверх окна по `PlaybackState` единственной MediaSession. Состояние
и заголовок кладёт страница (мост `AnimoriMedia`), команды возвращаются в
`window.__amMedia*` и доходят до того же кода плеера, что и клавиши экрана.

## Вход в AniList

Страница логин не вводит: оболочка отдаёт адрес авторизации системному
браузеру, приёмник на `127.0.0.1:48513` ловит возврат, страница-стрелочник
просит вернуться в приложение. Запасной путь — ручная вставка токена
(`animori_auth_submit`).

Токен хранится в `animori-settings.json`; читает и пишет его только Rust
(`auth.rs`), в журнал не попадает.

## Сеть и журнал

Запросы страницы идут `Bridge.http` с белым списком https-адресов
(`capabilities/default.json`); видео через hls.js — XHR самой страницы под
CSP `connect-src`. Журнал оболочки пишется файлом, в release уровень — warn;
экран журнала открывается адресом `#/log`.

## Устройство репозитория

| Каталог | Что в нём |
| --- | --- |
| `packages/core/src` | Общее ядро: `api`, `core`, `bridge`, `utils` |
| `packages/core/tests` | Наборы общего ядра и заглушка моста |
| `apps/android` | Приложение для телефона |
| `apps/android-tv` | Приложение для телевизора |
| `apps/windows` | Настольное приложение |
| `docs` | Документация: правовая в корне, инженерная в `docs/dev/` |

Граница ядра проверяется отдельно: `typecheck:shared` собирает ядро в проекте,
где каталога `src/app` не существует, и стрелка из ядра в надстройку роняет
сборку.

Сборка и проверки:

```bash
npm ci                                      # корень
npm test                                    # ядро, потом все приложения
npm run typecheck                           # все приложения
npm run build:android
```

Разработка идёт из каталога приложения:

```bash
cd apps/android && npm run tauri -- android dev
```

### Выпуски

| Продукт | Тег | Что собирается |
| :--- | :--- | :--- |
| Телефон | `android-v<версия>` | `arm64` и `armv7` |

Номер в теге сверяется с `package.json` приложения; расхождение роняет прогон.
Файлы телефона называются `AniMori_<версия>_<разрядность>.apk`; разрядность
приложение выбирает по себе.

Канал обновлений Windows занимает `releases/latest`, поэтому выпуск телефона
помечен предварительным: иначе перехватит адрес, на котором держится настольный
апдейтер. Подробнее — в `docs/RELEASES.md`.
