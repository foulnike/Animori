# Устройство

## Слои

| Каталог | Роль |
| --- | --- |
| `packages/core/src/` | ядро: данные и правила без DOM. Об интерфейсе и об оболочке не знает |
| `src/app/` | надстройка: экраны, компоненты, роутер, темы |
| `src-tauri/` | оболочка на Rust: окно, команды, файлы, прокси канала окна |

Границу держит `npm run typecheck:shared`: в этой проверке каталога `src/app` не
существует, поэтому любая стрелка из ядра в надстройку ломает сборку.

Общий код не выбрасывают под продукт, который его сейчас не зовёт: ядро одно на все
продукты, и то, что приставка не запускает, телефон умеет. Место, которое сегодня
никто не зовёт, помечается комментарием с тем, кто его зовёт — см. `core/cloud.ts`,
`saveCopy`. Полное правило — инвариант 19 в `../windows/CONVENTIONS.md`.

| Модуль | Что делает |

| `shikimori*.ts` | Шикимори: русские имена, описания, хронология, журнал, поиск |

## Мост

`IBridge.ts` — тип обоих сторон: `storage`, `files`, `exportFile`, `http`, `anilist`,
`clipboard`, `shell`, `proxyDiagnostics`.

Единственная точка входа — `TauriBridge.ts`. К `@tauri-apps/*` никто не обращается
напрямую, только через мост: `@/bridge` за типами, `@bridge-impl` за реализацией.
Псевдопуть прописывается в трёх местах: `vite.config.ts`, `tsconfig.json`,
`tsconfig.shared.json`; расхождение даёт зелёную сборку при красном тайпчеке или наоборот.

Файлы внутри `packages/core/src/bridge` импортирует только `TauriBridge.ts`.

## Экраны

Роутер: смена по адресу в строке браузера; повтор того же адреса переходом не считается.
Направление задаёт `SCREEN_DEPTH`: вкладки вровень, карточка глубже вкладок, студия и
плеер глубже карточки.

Девять экранов: `home`, `lists`, `history`, `search`, `media`, `studio`, `player`,
`settings`, `log`. В меню пять вкладок: Главная, Моё, История, Поиск, Настройки.
Карточка, студия, плеер и журнал в меню не стоят: вход в них из списков, поиска,
карточки и адресом `#/log`.

Настройки — мозаика из шести плит (`components/SettingMark.vue`); панель открывается окном
поверх экрана (`components/SettingsSheet.vue`).

Новый экран — три места: имя в `routes.ts`, подпись в `SCREEN_TITLES`, компонент в
`App.vue`; меню — четвёртое и необязательное.

## Мост: команды

| Команда | Что делает |
| --- | --- |
| `animori_reload`, `animori_restart` | перезагрузить окно, перезапустить приложение |
| `animori_open_external` | отдать адрес системе |
| `animori_auth_start/_submit/_status/_logout` | вход в AniList; интерфейс приставки их не зовёт |
| `animori_anilist_query` | запрос (query) к AniList; `mutation` отклоняется |
| `animori_file_read/_write` | чтение и запись своих файлов |
| `animori_storage_read/_write` | чтение и запись настроек |
| `animori_export_pick_dir`, `animori_export_write` | выгрузка списка файлом; интерфейс приставки их не зовёт |
| `animori_proxy_status/_probe` | состояние и проба прокси канала окна |

Права — один файл `src-tauri/capabilities/default.json`. Список адресов в нём
окончателен: промах плагин отклоняет до сети.

`anilist` отделена от `http`: адрес и пропуск живут только в Rust, наверх идёт тело запроса и
просьба его подписать — токен не покидает оболочку.

Токен AniList не покидает Rust: команда принимает тело запроса, заголовок авторизации
подставляет оболочка. Тела с `mutation` команда отклоняет до подстановки токена
(`reject_mutation` в `anilist.rs`) — приложение только читает список. Входа в AniList
на приставке нет.

## Оболочка

Журнал оболочки пишется файлом, в release уровень — warn; экран журнала открывается адресом `#/log`.

## Обновление

`app/update.ts` — сверка версии с выпусками GitHub и окно предложения. Своего
апдейтера у Tauri на Android нет (`tauri-plugin-updater` только для десктопа):
приложение читает список выпусков общего репозитория, берёт первый с приставкой
`android-tv-v`, выбирает файл по разрядности и отдаёт адрес оболочке.

Ни `latest.json`, ни `releases/latest` приставка не читает: она находит свой выпуск по
тегу и не смотрит на флаги `draft` и `prerelease`. Поэтому релиз приставки помечен
предварительным не ради обновления, а чтобы не занимать адрес `releases/latest`,
который вычисляется GitHub и нужен настольным сборкам 3.0.x. Причина и правило — в
`docs/RELEASES.md`.

## Интерфейс

Правила действуют под классом `.am-lite` на `<html>`, который ставит
`app/platform.ts` по признаку Android. На десктопе их нет.

### Пульт

`app/dpad.ts` водит фокус сам: пространственная навигация движка отключена. Цель ищется
по геометрии — `nearest()` сравнивает отрезки, смещение в ней означает зазор между ними.

- `preventDefault` на стрелках стоит всегда, кроме `.am-pick` и раскрытого
  `.am-roll` — они пропускают управление дальше.
- Стрелка у органа, который ею листает значение, на приставке молчит: стрелки заняты
  обходом, шаг делают кнопки. Так живут год выхода и кадры в просмотре.
- Рельс — отдельная полоса: вход влево, выход вправо, двусторонний ход запрещён.
- `data-am-beside` — спутник крупной соседки: вверх-вниз водят по целям, кнопка рядом
  берётся вбок.
- Верхняя строка окна ведёт вверх к крестику (`data-am-last`), даже если по горизонтали
  с ним не перекрывается: панель настроек стоит колонкой. Вверх и вниз последний проход
  ищет цель и без перекрытия — страница ходит только по перекрытию.
- Фокус ставится с проверкой: отказ `focus()` повторяется на следующем такте, иначе
  нажатие пропадает молча.
- «Назад»: аппаратная кнопка достаётся оболочке раньше страницы — `app/back-stop.ts` и
  `MainActivity.kt`. Последний добавленный отвечает первым.

### Кромка фокуса

Кромка рисуется `outline`, а не `box-shadow`: тень срезается `overflow`. Правило в
`app/styles/theme.css`:

```
.am-lite :focus-visible {
  outline: 2px solid rgb(var(--am-accent-rgb) / 0.9);
  outline-offset: -2px;
  box-shadow: inset 0 0 0 999px rgb(var(--am-accent-rgb) / 0.18);
}
```

`inset`-тень заливает площадь поверх собственного фона элемента. Где форму рисует
потомок, кромку рисует потомок: обойма портрета, цветок сакуры, поле ввода; хозяину
ставят `outline: none`. Постеру и плите человека кромка не нужна — у них свой отклик
формой. `--am-sh-ring` (1 px) — обводка поверхности, а не кромка фокуса.

### Ховер

На приставке ховер не работает, и это правило, а не пропуск: браузер не пересчитывает
наводное без настоящего движения, и подсветка остаётся на элементе, над которым курсора
уже нет — на экране два курсора, настоящий и чужой.

Страж `:hover:where(:not(.am-lite *))` закрывает ховерные правила под `am-lite` целиком:
вес его нулевой, на ПК поведение не меняется. «Здесь ты» говорит только кромка фокуса.
Точечные метки `am-tile--key` и `am-side--open` остались: они лечат запоздавшее
`:focus-visible`. Подписи от наведения (`app/tip.ts`) закрыты отдельно: показ без
свежего движения наводкой не считается, а чужую плашку пульт снимает первым же
направлением (`hideStaleTip`).

### Плавность

- Ускорение полок — `contain: layout paint style`.
- Лагает шаг: мерить крайние значения. Приставка шумная — сравнивать чередующиеся
  замеры.
- Размытие подложки стоит около ста миллисекунд на кадр, поэтому под `.am-lite`
  оно гасится целиком (`.am-lite *`). Рельс — исключение: подложка под ним
  статична, а размытие ему возвращает правило ниже.

### Рельс

Свёрнутая подпись место занимает: пункту `padding: 0; gap: 0`, подписи
`width: 0; height: 0; overflow: hidden`. Значок рисуется `display: grid;
place-items: center`, векторы — в `RailIcon.vue`, величина знака подбирается по чернилам.

При размытии плотность (`html.am-lite .am-side`) — 80 % панели: остаток затемнения
превращает перекрытое в пятна. Сборка без `backdrop-filter` держит плотную подложку.

### Темы

`app/appearance.ts` ставит `data-am-skin` на корень: фон окна и скроллбары задаются
выше любого экрана. Тем три. Цвета, радиусы и тени экраны берут только из
`app/styles/theme.css`.

### Мелочи

- Свои всплывающие подписи (`app/tip.ts`) вместо `title`: плашка одна на окно и живёт
  в `body`.
- Окно человека (`app/person-layer.ts`) — общий слой, а не состояние компонента.
- Плитки: наблюдатель `app/see-tile.ts` один на окно; просьба одноразовая.
- Сакура: геометрия одна на два контекста (`app/sakura.ts`), числа — в шапке
  `SakuraBloom.vue`.
- Подписи предметной области — `app/labels.ts`: незнакомый ключ показывается как есть.
- Перехват фокуса стоит в фазе захвата: `setTimeout(…, 0)` опаздывает.

Мост `AnimoriUpdate` (`MainActivity.kt`) — два метода: `abi()` и `install(url)`. Второй
возвращает `false`, когда нет права устанавливать пакеты, и уводит в настройки
Android. Целостность проверяет система: установка встаёт только на файл, подписанный
тем же ключом.

Проверка идёт при старте, только на `am-lite`: на компьютере моста нет. Имена файлов
выпуска окончательны: `AniMori_<версия>_<armv7|arm64>.apk`.

## Признак слабой платформы

`app/platform.ts` ставит класс `am-lite` на `<html>` до `createApp()`. Признак один —
Android. Что глушится — в `app/styles/theme.css` у `.am-lite`, см. раздел «Интерфейс»
выше.

`canOpenOutside()` оттуда не берётся: браузер — умение оболочки, и объявляет его
мост (`Bridge.shell.can.browser`).

## Источники данных

| Источник | Что даёт |
| --- | --- |
| AniList (GraphQL) | каталог, тайтлы, люди, расписание, полки главной |
| Шикимори (REST + GraphQL) | русские имена, описания, хронология, журнал, поиск по-русски |
| Kodik, Aniliberty | видео |
| Яндекс Диск | облачная копия списка |
| `animori-data` | датасет русских названий и карта MAL ↔ AniList |

Клиенты — `packages/core/src/api/`, стратегия — `packages/core/src/core/`. Зависимости идут
из `api` в `core`, не наоборот.

### Датасет названий

Собирается в отдельном репозитории `foulnike/animori-data` и выходит раз в неделю. Клиент тянет его сам:

1. при старте `updateDatasetNamesInBackground()` спрашивает опись `index.json` по
   постоянному адресу `releases/latest/download`, с `If-None-Match`;
2. `304` означает «тот же выпуск» — тела нет, сравнивать нечего;
3. если выпуск новее, качаются оба файла, сверяются по `sha256` и заменяют слепок целиком;
4. новый выпуск начинает работать со следующего запуска: в память текущего он не попадает.

Между проверками — `LIFE_DATASET_CHECK` (12 часов). Разброс считается от даты
установленной сборки. Неудача час проверки не сдвигает. Зеркала у клиента нет.

### Темп и здоровье

`api/rate-limit.ts` — один ограничитель на источник: лимит считается по IP, а не по
клиенту. `once()` склеивает одинаковые вопросы, пауза считается по остатку окна.

`core/net-health.ts` ведёт учёт доступности: суждение одно (`getOutage`), проба одна
(`runProbes`), не чаще `PROBE_COOLDOWN_MS` и не поверх идущего. Заговорить с человеком —
после двух неудач подряд. Хостов в модуле нет.

### Прокси

Каналов три:

1. запросы приложения — через мост, `basicAuth` в `TauriBridge.ts`;
2. запросы к AniList — из процесса оболочки, `anilist.rs`;
3. канал самого окна — `proxy.rs`, только Windows и WebView2.

На приставке работает два из трёх: канала окна нет.

Проверка — живым запросом через мост (`api/proxy-check.ts`). Исход пробы в `net-health`
не идёт. Смена адреса требует перезапуска для канала окна; запросы программы
подхватывают её сразу.

### Различение «нет» и «не доехало»

`null` означает и «перевода нет», и «ответ не доехал». Источник отвечает `ready` /
`none` / `fail`; сбой не запоминается. Отказы держатся отдельными ключами — `memory`,
`names`, `noname`.

### Сроки

`core/cache-life.ts` — одно место на всех. Разброс ±20 % считается от ключа.
Бессрочное — тоже срок, `LIFE_FOREVER`.

### 18+

Отбор — только через `core/adult.ts`, по тумблеру `settings.showAdult`. Отбор на слое
показа: прячется карточка, а не вход в плеер. Возраст формальный: `ADULT_AGE`,
`ageAt`, `adultByBirth`.

У строк отбора метки нет. Полки витрины собираются заранее и сбрасываются
`forgetRecs()` при смене тумблера. Взрослых источников видео нет.

## Видео

### Источники

Реестр — `api/video-sources.ts`, единственное место, где источники перечислены; ядро
знает только форму (`core/video.ts`). Порядок в реестре — порядок перебора на экране:
сначала открытый API, потом цепочки.

| Источник | Как устроен |
| --- | --- |
| Anilibria (`anilibria.top`) | открытый API, адреса HLS лежат в ответе; ни подписей, ни срока. Чужих номеров не знает: путь к релизу — точное совпадение имени, год как разводящий признак |
| Kodik | поиск по номеру Шикимори → страница серии → `POST /ftor`. Адреса HLS зашифрованы сдвигом латиницы и base64, величина сдвига подбирается перебором. Вход только по номеру Шикимори |

Метка доступности (`core/playable.ts`): очередь на видимое, по работнику на источник,
ответы складываются. Срыв — не ответ, молчание — «не знаю». Anilibria в метке не
участвует; у Kodik — `presenceCost: 'each'`.

Сборка `hls.js` подменяется лёгкой — alias в `vite.config.ts`. Полная тянет около
594 КБ; лёгкая собрана из тех же исходников без DRM, субтитров, вторых дорожек, CMCD,
HEVC, AC-3 и рекламных вставок. Шов стоит в конфиге сборки, а не импортом
`hls.js/light`: у лёгкой сборки нет своего `.d.ts`, типы остаются от полной.

### Плеер

`hls.js`-обёртка (`screens/player-hls.ts`): открыть манифест, сесть на секунду,
пережить срыв сети и убрать за собой. Библиотека, а не тег: движок окна HLS не умеет.

`screens/player-view.ts` — данные экрана: карточка, перебор источников, озвучки,
серии, ссылки. Ссылки не кэшируются (актуальны часы): устаревшую обновляют молча
(`renew`), а открытое обновление — когда молча не помогло. Дорожка выбирается по
высоте (`pickTrack`).

### Ввод

`screens/player-input.ts`. Пульт приезжает обычной клавиатурой: стрелки, «ОК»,
«назад», медиа-клавиши. Отдельного вида ввода под телевизор нет.

### Память просмотра

`screens/player-keep.ts` — одна запись: где остановились, что выбрали, что смотрели.
История — не метка: метка умирает по досмотру, ключ истории склеен из аниме и серии
без озвучки.

## Устройство репозитория

| Каталог | Что в нём |
| --- | --- |
| `packages/core/src` | Общее ядро: `api`, `core`, `bridge`, `utils` |
| `packages/core/tests` | Наборы общего ядра и заглушка моста |
| `apps/windows` | Настольное приложение |
| `apps/android-tv` | Приложение для телевизора |
| `apps/android` | Приложение для телефона |
| `docs` | Документация: правовая в корне, инженерная в `docs/dev/` |

Граница ядра проверяется отдельно: `typecheck:shared` у каждого приложения собирает ядро в проекте,
где надстройки не существует. Стрелка из ядра в экран или оболочку роняет сборку.

Сборка и проверки:

```bash
npm ci                                      # корень
npm test                                    # ядро, потом все приложения
npm run typecheck                           # все приложения
npm run build:android-tv
```

Разработка идёт из каталога приложения:

```bash
cd apps/android-tv && npm run tauri -- android dev
```

### Выпуски

| Продукт | Тег | Что собирается |
| :--- | :--- | :--- |
| Телевизор | `android-tv-v<версия>` | `armv7` и `arm64` |

Номер в теге сверяется с `package.json` приложения; расхождение роняет прогон. Файлы приставки и
телефона называются `AniMori_<версия>_<разрядность>.apk`; разрядность приложение выбирает по своей.

Канал обновлений Windows занимает `releases/latest`, поэтому выпуск приставки помечен
предварительным: иначе перехватит адрес, на котором держится настольный апдейтер. Подробнее — в
`docs/RELEASES.md`.
