# Выпуски: один репозиторий, три продукта

Правила выкладки в общем репозитории. Читать, прежде чем добавлять сюда
продукт.

## Откуда взялось

Пока приложение было одно, обновление работало на адресе, который GitHub вычисляет сам:

```
https://github.com/foulnike/Animori/releases/latest/download/latest.json
```

`releases/latest` — не имя, а вычисление: самый поздний обычный релиз во всём
репозитории. Черновики и предварительные в расчёт не входят.

В 3.1.0 в репозитории стало два продукта, и адрес стал общим. Приставка вышла позже
настольного приложения, забрала `releases/latest`, а `latest.json` в её релизе нет —
вместо него APK. Старые сборки Windows получили 404 и молча перестали обновляться: ни в
одном логе при этом ничего не было. Починили тем, что релиз приставки сделали
предварительным.

## Два разных механизма, не путать

| | Как ищет обновление | Нужен ли `latest.json` |
| :--- | :--- | :--- |
| Настольное | Свой апдейтер Tauri: адрес из `tauri.conf.json`, манифест, подпись ключом | Да |
| Приставка | Свой код: список релизов, фильтр по префиксу тега `android-tv-v`, выбор APK по разрядности | Нет |
| Телефон | Свой код: список релизов, фильтр по префиксу тега `android-v`, выбор APK по разрядности | Нет |

Приставка и телефон не читают ни `latest.json`, ни `releases/latest`. Их апдейтеры
вообще не смотрят на флаги `draft` и `prerelease`: находят свой выпуск по тегу.
Поэтому предварительный статус у их релизов — не способ обновляться, а способ
**не занимать чужой адрес**. Проверено на живом ответе GitHub: релиз
`android-tv-v3.1.0` помечен предварительным, приставка его находит и обновляется.

## Правило

**`releases/latest` принадлежит настольному приложению. Ни один другой продукт
в этом репозитории его не занимает.**

Основано на две вещи, обе проверены:

- предварительные релизы `releases/latest` пропускает — GitHub их не считает;
- список релизов `/releases` предварительные содержит, поэтому предварительный релиз
  приставки виден её апдейтеру.

Настольное приложение 3.1.0 и новее этот адрес **не читает**: его апдейтер ходит в
собственный канал. Адрес держится ради сборок 3.0.x и старше, у которых адрес манифеста
вшит в бинарный файл:

```
https://github.com/foulnike/Animori-Desktop/releases/latest/download/latest.json
```

`Animori-Desktop` — прежнее имя того же репозитория, GitHub перенаправляет. Сборка
новее 3.0.0 сменить адрес не может: он уже в бинарнике.

## Что делать новому продукту

1. **Свой канал**, если обновление идёт через `latest.json`: релиз с постоянным тегом
   `<продукт>-latest`, в нём один файл — манифест на последнюю сборку. Образец — шаг
   «Канал обновлений windows-latest» в `.github/workflows/release.yml`. Своего
   апдейтера на Android нет, поэтому приставке и телефону канал не нужен: они ищут
   по тегу. Мобильным портам на Android из магазина не нужно ни того, ни другого.
2. **`prerelease: true`** на релизе, если продукт сам обновляется с GitHub. Иначе он при
   случае заберёт `releases/latest` и отрежет обновление всем, кто сидит на 3.0.x.

3. **`draft` нельзя.** Черновик не виден в анонимном списке релизов, и апдейтер
   приставки его не найдёт — обновление пропадёт совсем.

4. **Свой префикс тега** для поиска: `android-tv-v`, `android-v`, `windows-v`.
   По нему апдейтер отличает свой выпуск от чужого.

5. **Своё имя канала, а не `releases/latest`**, в конфиге: адрес вписывается в
   бинарный файл при сборке, и смена его не доедет до уже установленных копий.

## Чего не ждать

Правило переживёт любой порядок выпусков: продукты не зависят друг от друга по
времени публикации. Но оно держится на соглашении, а соглашение нарушается
тихо — ошибки не будет ни в одном логе, сбой увидят только люди, сидящие на
3.0.x.

Автоматической проверки, которая бы это ловила, в конвейерах пока нет: стоит
добавить в шаг выкладки приставки один запрос `releases/latest/download/
latest.json` с проверкой, что версия всё ещё настольная.

## Когда правило можно ослабить

Когда 3.0.x и старше уйдут в историю: тогда на `releases/latest` перестанет
кто смотреть, и предварительный статус у приставки станет не нужен. До тех пор
он обязателен — это единственная ниточка, по которой старые копии ещё
получают обновления.
