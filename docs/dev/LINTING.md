# Линтер и форматтер

`npm run lint` — ошибки, чинит автоматически `npm run lint:fix`.
`npm run format` — форматирование, `npm run format:check` — только проверить.

## Почему так разделено

ESLint ищет ошибки, Prettier приводит вид. Правила оформления у ESLint выключены
(`eslint-config-prettier` идёт последним в конфиге), иначе два инструмента спорят за
одну и ту же строку и правки начинают «плавать».

## Что проверяется

236 файлов: `.ts`, `.vue`, `.mjs`. Активно около 160 правил. Проверено, что они не
молчат: линтер ловит `no-var`, отсутствие `:key` в `v-for` и другие настоящие огрехи.

Неиспользуемые переменные в TypeScript отключены осознанно: их и так ловит `tsc`
(`noUnusedLocals`), а дубль даёт вдвое больше шума.

## Чего пока нет

`format:check` в CI включён — в джобе `core` (`ci.yml`). `lint` в CI — в четырёх джобах
(`core`, `windows`, `android-tv`, `android`).

Форматирование можно применить разом: `npm run format`.

## Если что-то сломалось

`npm run lint:fix` чинит автоматически то, что чинится безопасно. Остальное — руками.
