# Зависимости и аудит

## Проверки

CI (`ci.yml`, задача `core`) на каждый пуш, PR и тег выпуска гоняет `npm audit --audit-level=high`.
Rust-дерево проверяет `cargo deny check` из каталога `src-tauri` каждого приложения, конфиг —
корневой `deny.toml`. Запускать его нужно именно оттуда: с `--manifest-path` из другого каталога
cargo-deny корневой конфиг не находит и падает на `advisories` и `licenses` без списков `ignore` и
`allow`.

Порог `high` оставлен сознательно: moderate в инструментах разработки не должен блокировать выпуск.
Moderate всё равно видны в журнале прогона и закрываются при ближайшем обновлении.

## Лицензии и перечень компонентов

`tools/gen-third-party.mjs` строит `docs/THIRD-PARTY.md` по тому, что реально входит в выпуски:
рантайм-зависимости интерфейса из `package-lock.json` (без инструментов разработки) и обычные
зависимости Rust из `cargo metadata --locked` по целевым платформам выпуска. Наборов три —
интерфейс, Rust для Windows, Rust для Android. MSI, NSIS и портабл несут один `AniMori.exe`,
у телефона и приставки одинаковый `Cargo.lock`, arm64 и armv7 отличаются двумя крейтами (они
помечены).

| Команда | Что делает |
| --- | --- |
| `npm run third-party` | пересобирает `docs/THIRD-PARTY.md` |
| `npm run third-party:check` | CI: перечень совпадает с lock-файлами, все лицензии из `[licenses].allow` в `deny.toml`, у каждого пакета найден текст лицензии |
| `node tools/gen-third-party.mjs --texts <продукт> --out <каталог>` | конвейер выпуска: `THIRD-PARTY-LICENSES.txt` с полными текстами и копия перечня |

Список разрешённых лицензий один на npm и Rust — `[licenses].allow` в `deny.toml`. Пакет,
который можно взять только под GPL, AGPL, LGPL или другой лицензией вне списка, валит CI и сборку
выпуска; добавлять его — отдельное решение о лицензии. Если у пакета нет файла лицензии,
генератор подставляет стандартный текст (MIT и BSD — с авторами из манифеста, Apache-2.0,
MPL-2.0 и BSL-1.0 — дословно из другого пакета набора) и помечает это в файле.

После обновления зависимостей: `npm run third-party` и закоммитить `docs/THIRD-PARTY.md`.

## Исключения в deny.toml

Все шесть исключений в `[advisories].ignore` — статус unmaintained у транзитных крейтов Tauri,
уязвимостей за ними нет. Отдельные задачи на них не заводятся: исправить их можно только
обновлением Tauri. Пересмотр происходит сам: когда Tauri уберёт крейт, cargo-deny выдаст
`advisory-not-detected`, и строку нужно удалить. Новое advisory в дереве Tauri в список не
попадает и валит CI.

## vue-tsc 3 и ссылки на элементы

vue-tsc 3 считает `ref="имя"` в шаблоне использованием переменной, только если она объявлена через
`useTemplateRef('имя')`. Обычный `ref(null)` под тем же именем при `noUnusedLocals` даёт TS6133.
Ссылки на элементы объявляются так:

```ts
const franList = useTemplateRef<HTMLElement>('franList')
```

`useTemplateRef` работает только синхронно в `setup` компонента; composable вроде `useMediaCard`
годится, потому что вызывается оттуда же.

## Обновление

1. Поднять версии в `package.json` корня и трёх приложений одинаково — `npm run sync:check` и
   `npm run drift` ловят расхождение.
2. `npm install`, затем `npm run fix:lock` (признак `optional` у платформенных пакетов, иначе
   `npm ci` на Linux падает с EBADPLATFORM).
3. `npm ci` и полный набор: `test`, `typecheck`, `lint`, `format:check`, `sync:check`, `drift`,
   `npm audit --audit-level=high`, `build:*`.
4. `npm run third-party` — пересобрать `docs/THIRD-PARTY.md`.
