# Дубликаты между продуктами: почему они остаются

Настольное приложение, приставка и телефон — три разных продукта в одном репозитории.
Копии файлов в парах `apps/windows` ↔ `apps/android-tv` и `apps/android-tv` ↔ `apps/android`
дублируются намеренно, и сливать их не нужно. `npm run drift` следит за тем, чтобы это
дублирование не превратилось в источник багов. Под сторожем и Rust-слой оболочки:
пары из `apps/*/src-tauri/src` лежат в том же снимке под ключами `src-tauri/…`.

Пара приставки и телефона — форк: мобильная копия стартовала идентичной ТВ и расходится
по мере тач-адаптации. Текущая разность фиксируется `npm run drift:accept`.

## Что на самом деле опасно

Опасна не сама копия, а **правка на одном краю без правки на другом**. На ТВ меньше настроек,
своя вёрстка модалок, нет гиперссылок — сейчас в 47 из 61 пары интерфейсов
`windows ↔ android-tv` код отличается по существу (в Rust-слое — 4 из 9 пар).
Слить их нельзя: различия продуктов станут неотличимыми от случайных.

Поэтому `drift` падает не на самом различии, а на его **росте сверх зафиксированного**. Разница,
которую выросли осознанно, подтверждается `npm run drift:accept` и становится нормой.
Разница, которую забыли, валит CI.

## Синхронные копии

15 файлов держатся одинаковыми по коду — 11 интерфейсных плюс четыре Rust-файла
(`src-tauri/anilist.rs`, `files.rs`, `storage.rs`, `main.rs`). Они перечислены в
`KEPT_IN_SYNC` в `scripts/drift.mjs` и проверяются отдельно: если такой файл разойдётся
по коду, прогон падает даже если разность мала. Комментарии в них унифицированы.

## Почему не переносим

11 интерфейсных файлов — это 1 239 значимых строк стороны Windows из 14 179 значимых строк её
интерфейса (около 9 %). Остальное слить нельзя по замыслу. Перенос потребовал бы нового пакета,
алиаса в четырёх конфигах и правки импортов — ради малой доли строк и при полной уже работающей
защите от забытых правок. Цена ошибки на порядок выше выигрыша.

Если эти файлы начнут активно меняться и разъезжаться по существу, `drift` покажет это сам,
и перенос станет осмысленным.

## Если всё-таки нужно

1. Проверить `npm run drift` — он покажет, какие из перечисленных в `KEPT_IN_SYNC` действительно
   разошлись.
2. Обновить список `KEPT_IN_SYNC`, если файл перестал быть синхронным.
3. Для нового общего места — не `packages/core`: ядро принципиально не зависит от `vue`
   и `hls.js`, и перенос туда сломал бы эту границу.
