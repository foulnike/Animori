# Соглашения

Правила кода и документации приложения. За большинством пунктов стоит дефект,
который уже случился.

## Слои и зависимости

```
apps/windows/src/app/      экраны, компоненты, роутер
        ↓  алиасами @/api, @/bridge, @/core, @/utils
packages/core/src/          api → bridge, core, utils
```

- Ядро (`packages/core`) не знает о надстройке. Проверяется отдельной сборкой:
  `npm run typecheck:shared` собирает ядро в мире, где каталога `src/app` не существует, и падает на
  любой стрелке из ядра в надстройку.
- Граница нужна не для красоты: ядро общее для двух продуктов, и перенос правки между ними
  остаётся дешёвым только пока ядро не знает, в какой оболочке работает.
- Между слоями импорт только алиасом, относительные пути — внутри своего каталога.
- К `@tauri-apps/*` никто не обращается напрямую, только через мост: `@/bridge` за типами,
  `@bridge-impl` за реализацией.
- Все сетевые вызовы — только в `core/api`: экран, стучащий в сеть сам, обходит ограничитель
  темпа и рано или поздно ловит 429.
- `packages/core/src/utils/` не импортирует ничего, кроме типов.
- Экран не ходит в сеть и в хранилище сам, только через слой данных.

## Инварианты

Нарушение каждого уже приводило к дефекту.

1. Каждый сетевой запрос берёт слот у ограничителя темпа и задаёт `credentials`. Для
   `graphql.anilist.co` всегда `omit`: с куками сервис отвечает 403 через Cloudflare.
2. Молчаливый `catch` запрещён. Либо обработка, либо запись в журнал.
3. Список меняется только через `editEntry()` из `core/collection.ts`. Правка ложится в память и в
   снимок — и остаётся здесь: на AniList из приложения не уходит ничего.
4. Взрослое отбирается только через `adult.ts` и только на слое показа. Из баз и с сервера оно не
   вырезается никогда. Свои списки исключением не считаются: тумблер один на всё приложение.
   Исключение одно, и оно про назначение, а не про удобство, — история просмотров: она не каталог, а
   запись о том, что человек уже смотрел.
5. Вложенные реактивные ссылки объявляются поверхностными.
6. Задачи смены роута идемпотентны.
7. Цвета и радиусы — только токенами темы.
8. Настройка, способная лишить программу связи, не управляется только из того места, которое без
   связи не откроется. Прокси — ровно такой случай: экран настроек обязан открываться на локальных
   данных.
9. Новый внешний адрес прописывается в разрешениях http в `capabilities/default.json`.
10. Новая команда оболочки заводится в трёх местах: `#[tauri::command]` и `invoke_handler` в
    `lib.rs`, `AppManifest::commands` в `build.rs`, разрешение в `capabilities/default.json`.
    Пропуск третьего даёт отказ в рантайме без ошибки компиляции. Проверяет `npm run sync:check`.
11. Для вызова команды из разметки добавляются тип в `IBridge` и реализация в `TauriBridge`.
12. Файл в приватном каталоге программы пишется только по имени из белого списка в
    `src-tauri/src/files.rs`. Проверка именно списком, а не разбором символов: иначе команда записи
    становится способом положить в каталог что угодно и под любым именем. Выгрузка XML идёт мимо
    этого списка, своей командой в `export.rs`: там место выбирает человек, а сторожем служит
    окончание имени и потолок размера.
13. **Срок хранения складской записи объявляется в `core/cache-life.ts` и проверяется при чтении**
    (`isFresh`), а не «по умолчанию бессрочно». Срок россыпью по модулям — это срок, которого нет:
    ответ на вопрос «почему программа спросила это во второй раз» должен читаться одним взглядом, а
    не обходом десяти файлов.
14. **Новый префикс склада вписывается в `KEY_PREFIXES` в `core/db.ts`.** Иначе записи нового вида
    молча уходят в «прочее» сводки, и первый же разговор про размер базы начинается с неверных
    чисел.
15. Команда, меняющая настройку канала, применяется перезапуском, а не перезагрузкой страницы:
    `animori_reload` прокси не применяет, нужен `animori_restart`. Путаница выглядит как «настройка
    не сохранилась».
16. **Родитель адресует корень чужого компонента только через `:deep()`.** Vue расставляет в
    scoped-правилах признак области видимости, и признак родителя достаётся корню ребёнка лишь
    тогда, когда корень у ребёнка один. У `ShotBox` корней пять — две панели да три окна через
    `Teleport`, — и правило `.am-board > .am-shots[data-v-…]` не совпадало ни с чем: в разработке
    работает, в собранном приложении нет, ошибки нет, доски пустая. Признак ставится на предка:
    `.am-board > :deep(.am-shots)`. Проверять правило на самом компоненте: макет или отдельная
    страница его не покажут. Ловушка ждёт и рядом: у `TuneBox` и `PeopleBox` корней тоже по два.
17. **Номер MAL переводится в запись каталога только через `core/media-parts.ts`.** Своя карта
    «номер → запись» — это молчаливый выбор «последняя победила»: одному номеру служба иногда
    отвечает несколькими записями, и что попадёт в карту, решает порядок ответа. Нужна одна запись —
    `pickEntry`, нужен порядок всех — `orderParts`.
18. **Дата рождения из проверки возраста не сохраняется нигде** — ни в файле настроек, ни в памяти,
    ни в снимке. Она не удостоверяет личность, а персональные данные там, где их не было, — цена без
    выгоды. Проверка в `adult.ts` (`ageAt`, `adultByBirth`) считает **полные годы**, а не
    разницу годов: время передаётся доводом, иначе её нельзя проверить в тесте. Негодная дата
    отвечает `false` — ошибка тут пускала бы вперёд, а не назад.
19. **Общий код не выбрасывают под продукт, который его сейчас не зовёт.** Ядро одно на все
    продукты, и функция, «мёртвая» на приставке, не мёртвая: телефон её умеет. Выбрасывание
    возвращает ровно то расхождение копий, ради которого заведён сторож, — правка перестаёт
    доезжать, а файлы снова расходятся. Вместо этого продукт объявляет, что умеет, и всё, что нужно,
    спрашивает объявление. Умения оболочки объявлены в мосте, `Bridge.shell.can`; у файлов и
    выгрузки — флагом `available`. Объявление лежит в мосте, потому что мост — единственная щель,
    которой общий код вправе пользоваться: объявление в надстройке спрашивали бы экраны, а знал бы
    его кто-то другой. Место, которое сегодня никто не зовёт, помечается комментарием с тем, кто его
    зовёт: иначе оно выглядит работающим — тесты зелёные — и стоит получаса ложных выводов, прежде
    чем выяснится, что вызова нет.

## Размер файла

Потолка в байтах нет. Повод остаётся предмет, а не число: файл делят, когда в нём две области,
которые правятся по отдельности и почти не ссылаются друг на друга. Делить по областям хорошо ещё и
тем, что мёртвая область потом вынимается одним движением.

Размер не повод делить. Документацию по размеру не делят тем более: разложенный по кускам справочник
читается хуже цельного, а повод — вторая предметная область.

## Комментарии

Комментарий объясняет причину, а не действие. «Увеличиваем счётчик» не нужно никому; «счётчик общий
на зеркала: лимит считается по IP» нужно всем.

Запрещены: хронология («правка после…», «статус на дату», «дело в N» — история в git),
комментарий, повторяющий имя функции, закомментированный код, ссылка на модуль, которого больше нет.

Длина строки — 100 знаков.

## Работа с репозиторием

Рабочая ветка одна — `main`.

Тайпчек звать отдельно не нужно: `build:app` сам начинает с `typecheck:all`. Неиспользованный импорт
роняет тайпчек, а значит и сборку. Правка чистых модулей ядра проверяется ещё и `npm test`.

Тело коммита — три-восемь строк о том, что было не так и что отвергнуто. Заголовок описывает
результат, тело — причину.

Алиасы слоёв прописаны в четырёх местах и правятся только вместе: `resolve.alias` в `vite.config.ts` и в
`vitest.config.ts`, `paths` в `tsconfig.json` и в `tsconfig.shared.json`. Расхождение даёт зелёную
сборку при красном тайпчеке или наоборот. Проверяет `npm run sync:check`.

`npm run fix:lock` возвращает признак `optional` платформенным пакетам в `package-lock.json`. npm
ставит его только вариантам, совпавшим с его собственной платформой, поэтому после любого
`npm install`, перезаписавшего замок, Linux-сборка падает на `npm ci` с `EBADPLATFORM`. Скрипт
запускают сразу после такого `npm install` и до коммита замка.

Выпуски и каналы обновлений — `docs/dev/RELEASES.md`.

## Документация

Документ описывает состояние, а не хронику. Устаревшее удаляется, а не зачёркивается: история уже
есть в git.

- Документ описывает только свой продукт. Про соседний — ровно столько, сколько нужно для решений в
  этом.
- Нет файлов с номерами. Разросся документ — значит в нём лежит неправда.
- Нет дат в заголовках разделов и пометок «отменено».
- Причина ценнее формулировки: через полгода возвращаются за «почему».
- Сухо и коротко. Вещь называют своим именем, уточнений и пояснений «зачем» не пишут.
- Утверждение сверяется с кодом. Код правится — правится и документ, в том же коммите. Проверить
  нечем или дорого — пишется как замысел и называется замыслом.
- Число пишется, когда на нём стоит решение, и сверяется при каждой правке соседнего абзаца.

Список документов — в `README.md` этой папки. Новый файл появляется только с новой предметной
областью.
