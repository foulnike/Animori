# Архитектура

Настольное приложение AniMori на Tauri 2. Ядро — `packages/core/src/`, экраны — `src/app/`, оболочка
— `src-tauri/`.

Приложение ведёт только аниме. Список односторонний: приезжает из AniList по входу, с Шикимори по
нику и файлом выгрузки MyAnimeList, хранится на устройстве и на сервер не уходит. Наружу уходит
выгрузкой в XML и копией в облако — `STORAGE.md`.

Данные склеиваются: каталог и списки — AniList, русские названия — датасет `foulnike/animori-data`,
чего в нём нет — Шикимори, персонажи и авторы — Шикимори, музыка — AnimeThemes, видео — Aniliberty и
Kodik. Датасет — `STORAGE.md`.

## Слои

```
apps/windows/src/app/      знает разметку
        ↓  алиасами @/api, @/bridge, @/core, @/utils
packages/core/src/          api, bridge, core, utils
```

Правила зависимостей и инварианты — `CONVENTIONS.md`.

## Мост

`packages/core/src/bridge/` прячет платформу за одним контрактом: что умеет среда, но не как. Ядро
не спрашивает, где работает.

| Группа             | Как устроено                                       |
| ------------------ | -------------------------------------------------- |
| `storage`          | `animori_storage_read` / `animori_storage_write`   |
| `http`             | плагин http, запрос идёт из Rust, без CORS         |
| `anilist`          | команда `animori_anilist_query`                    |
| `clipboard`        | плагин clipboard-manager                           |
| `shell`            | перезагрузка, полный экран, внешняя ссылка         |
| `files`            | `animori_file_read` / `animori_file_write`         |
| `exportFile`       | выбор папки и запись файла: XML и звук темы        |
| `proxyDiagnostics` | щуп прокси из Rust, живой запрос и состояние входа |

`anilist` отделена от `http`: адрес и пропуск только в Rust, наверх идёт тело запроса и
просьба его подписать — токен не покидает оболочку.

`files` отдаёт наружу имя, а не путь: каталог выбирает оболочка. Имён два — `animori-snapshot.json`
и `animori-dataset.json`, белый список в `files.rs`, потолок записи 8 МБ, запись идёт во временный
файл с переименованием.

`exportFile` устроена наоборот: путь выбирает человек диалогом, сторожем служит окончание имени.
Единственное место, где программа пишет вне своего каталога, и пишет туда только `.xml`.

У `files` и `exportFile` есть признак `available`: вне оболочки обе группы есть, но ничего не
делают.

## Сеть и темп

`api/rate-limit.ts` заводит ограничитель на источник, а не на домен: лимит считается по IP, и
зеркала делят один бюджет.

| Источник                                                 | Интервал   | Потолок за минуту           |
| -------------------------------------------------------- | ---------- | --------------------------- |
| Шикимори, AnimeThemes, GitHub, Aniliberty, Kodik | 300 мс     | 60                          |
| AniList                                                  | из потолка | старт 30, предохранитель 90 |

`acquireSlot()` — единственный вход, слоты по одному. Сверх минутного окна держится секундное: три
запроса в секунду в первые десять секунд после пуска, дальше восемь.

Один ограничитель у Шикимори делят `shikimori.ts` и `shikimori-people.ts`, а `shikimori-user.ts`
идёт мимо него — там единичные запросы по кнопке.

Плавающий потолок включён только у AniList: остальные заголовков не присылают. Ответ 429 режет
потолок вдвое и закрывает рост на пять минут, ниже шести запросов в минуту потолок не опускается.

## AniList

`api/anilist.ts` — единственная точка GraphQL и держатель общей паузы; запросов на запись нет.
Заголовки читаются из любого ответа, включая ошибки, в любом регистре имени: мост в Rust имена
понижает. Нулевой `x-ratelimit-remaining` ставит паузу до `x-ratelimit-reset`, но не длиннее минуты.
Отказ сервера (403, 408, всё от 500) — пауза 30 секунд с удвоением до пятнадцати минут, успех
обнуляет серию. Паузу дольше десяти секунд вызов не высиживает, а бросает ошибку с остатком.

403 неоднозначен: AniList отдаёт его и при закрытии доступа, и когда сервис лёг. При отказе в журнал
выписываются `cf-ray`, `cf-mitigated`, `cf-cache-status`, `retry-after`, `x-ratelimit-*` и `server`;
тела ответа в журнале нет.

## Слой данных

Порядок пуска держит `app/main.ts`: параллельно `loadSettings()` и `initSplash()`, затем
`setLogEnabled()`, `startAppearance()`, `installGlobalErrorHandlers()`, монтирование `App` вместе с
`errorHandler`/`warnHandler` Vue и сразу за ним `hideBoot()`, `initCollection()`, `initDatasetNames()`
и `updateDatasetNamesInBackground()`. Настройки первыми — иначе первая перерисовка идёт по
умолчаниям; коллекция поднимается после монтирования, иначе чтение снимка задержало бы первую
отрисовку. Заставка старта (`#boot`, картинка `src-tauri/icons/128x128.png`) лежит в
`src/app/index.html` и снимается после монтирования.

Записи коллекции живут словарём по номеру тайтла; правка идёт через `editEntry()` и никуда не уходит
— ложится в память и в снимок, а правка неизвестного тайтла создаёт пустую запись. Перенос выбирает
человек: `mergeFromServer` (основа — ответ сервера, чего там нет, остаётся) и `replaceFromServer`
(список становится ровно серверным, с подтверждением). Тот же выбор у `pullFromShikimori` и
`pullFromMalFile`, с оговорками: хозяин списка не меняется, ответ забирается целиком до изменения
памяти, а у файла метки правки может не быть — запись считается старейшей. Рядом —
`unlinkCollection` и `forgetCollection`.

Путь чтения имени четырёхуровневый: память запуска, датасет, склад, сеть. Ответ «такого номера в
файле нет» запоминается, сетевой сбой — нет. Описание и оценки идут тремя уровнями: память, склад
карточек, сеть. Разрез «имя» и «карточка» сделан в `core/media-title.ts`: `NAME1_` и `RU4_`.

Экран ничего не знает про сеть и хранение: читает память через `collection-view.ts`, меняет список
через `editEntry()`, имена берёт у `media-title.ts`, облик — у `media-looks.ts`, взрослое отбирает
через `adult.ts`. Подписи — в `app/labels.ts`.

Единственный модуль в `core/` без вызывающих в `src/` — `qr.ts`: QR-код для входа, зовётся только тестом.

## Прокси и учёт сети

AniMori работает с AniList через прокси-канал — настройку соединения, канал — часть приложения.

- `core/proxy.ts` — настройка и ключи хранилища. Модуль чистый: его читает и прикладной код, и мост.
- `core/proxy-settings.ts` — та же настройка со стороны разметки плюс вопрос о перезапуске. Разбор
  значений обязан совпадать с Rust: ключи читают `proxy.rs`, `anilist.rs` и этот модуль.
- `core/net-health.ts` — суждение о доступности (`getOutage`) и одна проба (`runProbes`). Учёт идёт
  по идентификаторам `anilist:graphql`, `shikimori:<домен>`, `animethemes`, `aniliberty`; адресов
  модуль не знает. Источник считается проблемным после двух неудач подряд, 404 считается успехом,
  отказ авторизации, 429 и отмена не учитываются.

Настройка не применяется на ходу: канал задаётся аргументом при запуске окна, нужен перезапуск.
Пароль прокси лежит в `animori-settings.json` открытым текстом. Ни одного адреса прокси в коде нет —
в интерфейсе и документации это настройка соединения.

## Оболочка

Окно `main` грузит сборку из `dist/app`, окно `login` держит форму входа. Больше окон нет:
`app.windows` в `tauri.conf.json` пуст, оба окна создаются кодом. Внешние ссылки уходят в системный
браузер командой `animori_open_external`. Перехвата навигации в коде нет, глобального объекта Tauri
в окне нет (`withGlobalTauri: false`), политика содержимого задана в `tauri.conf.json`
([CSP.md](../CSP.md)).

### Команды и права

Разрешения одни — `capabilities/default.json`, и только окну `main`: окно входа грузит чужую
страницу.

| Команда                                                          | Зачем                                                    |
| ---------------------------------------------------------------- | -------------------------------------------------------- |
| `animori_anilist_query`                                          | запрос (query) к AniList из Rust; `mutation` отклоняется до подстановки токена |
| `animori_auth_start`, `_submit`, `_status`, `_logout`            | вход, ручная вставка пропуска, срок, выход               |
| `animori_file_read`, `animori_file_write`                        | снимок списка и датасет в профиле                        |
| `animori_export_pick_dir`, `animori_export_write`                | выгрузка XML                                             |
| `animori_track_pick_dir`, `animori_track_write`                  | запись звукового файла темы                              |
| `animori_proxy_status`, `animori_proxy_probe`                    | исход настройки сети и проба адреса                      |
| `animori_open_external`                                          | ссылка в системный браузер                               |
| `animori_devtools`                                              | инструменты разработчика                                 |
| `animori_cast_panel`                                             | системная панель трансляции, только Windows              |
| `animori_reload`, `animori_restart`, `animori_toggle_fullscreen` | перезагрузка страницы, перезапуск процесса, полный экран |

`animori_reload` и `animori_restart` путать нельзя: **перезагрузка страницы не применяет прокси** —
ключи запуска WebView2 читаются один раз, при создании первого окна.

`animori_anilist_query` принимает тело запроса от разметки и подписывает его токеном, поэтому
отсекает `mutation` до подстановки токена (`reject_mutation` в `anilist.rs`): приложение только
читает список, а закрытие начинается в Rust — команда не должна оставаться способом писать в
аккаунт, даже если окно скомпрометировано. Проверяется поле `query`; строки в `variables` (поиск
пользователя) проходят свободно.

Внешние адреса для `http:default` перечислены в том же файле прав, включая `cloud-api.yandex.net` и
раздатчики файлов Яндекса. Список живёт до сети: промах плагин отклоняет до всякого запроса.

Новая команда — всегда три места: `invoke_handler` в `src/lib.rs`, `COMMANDS` в `build.rs` и
`permissions` в `capabilities/default.json`.

### Вход

Форма открывается в окне `login`, которое идёт через наш прокси. Пропуск возвращается на
`http://127.0.0.1:48513/relay`: приёмник слушает только петлю и гаснет через пять минут. Возврат
принимается только с `state` — одноразовым nonce, который приёмник подставляет в запрос входа и
сверяет на `/token`; без совпадения возврат отклоняется. Разметка видит только факт входа и срок,
ручная вставка — запасной путь. **Адрес возврата задан не в репозитории**, а в консоли разработчика
AniList: при смене адреса приёмника правится консоль, а не исходник.

### Прокси

Трафик идёт двумя каналами: страница — через ключи запуска WebView2, запросы из Rust — через опцию
клиента. `proxy.rs` сводит всё к одному из пяти исходов: выключено, неверные данные, адрес не
отвечает, канал окна не поддерживается, применено; исход доступен интерфейсу командой
`animori_proxy_status`, читатель — `ProxyBox.vue`. Прокси, который соединение принимает и не пускает
наружу, TCP-щупом не отличить: второй шаг в ядре (`api/proxy-check.ts`). За пределами Windows
применён канал окна не бывает — переменную окружения читает только WebView2. `proxy_auth.rs`
подставляет логин с паролем на событие базовой авторизации, только под Windows.

### Сборка

Режим один: корень `src/app`, выход `dist/app`.

- `@bridge-impl` → `packages/core/src/bridge/TauriBridge.ts`; `@/api`, `@/bridge`, `@/core`,
  `@/utils`, `@` — соответствия каталогов, `@` последним. Те же соответствия в `tsconfig.json` и
  `tsconfig.shared.json`.
- `__ANIMORI_PLATFORM__` = `'app'`, `__ANIMORI_VERSION__` — из `package.json`.
- `minify: 'oxc'`, `target: 'es2022'`, `emptyOutDir: true`.
- `hls.js` берётся лёгкой сборкой `hls.light.mjs`; путь ищет `require.resolve`.

`beforeBuildCommand` и `beforeDevCommand` зовут `npm run build:app`, `frontendDist` смотрит на
`dist/app`, а `build:app` начинается с `typecheck:all`. `npm test` гоняет vitest по
`tests/**/*.test.ts`, мост подменяется (`@bridge-impl` → `packages/core/tests/mocks/bridge.ts`),
окружение — `happy-dom`.

Номер версии один, в `package.json`; `tauri.conf.json` берёт его строкой
`"version": "../package.json"`. Теги выпуска — `windows-v<версия>`.

### Выпуск и обновление

Собираются два установщика, NSIS и MSI; портативный архив добавляет воркфлоу отдельным шагом из
готового `AniMori.exe`. Обновление идёт по NSIS (`updaterJsonPreferNsis` в `release.yml`: все
установленные копии поставлены им же, иначе клиент пошёл бы обновляться через `msiexec`). Манифест
`latest.json` генерирует tauri-action, режим установки `passive`, ключи подписи лежат в секретах
сборки: неподписанное обновление клиент не примет.

Апдейтер ходит не в `releases/latest`, а в собственный канал
`releases/download/windows-latest/latest.json`: в общем репозитории этот адрес вычисляется GitHub
как «последний обычный релиз», и при двух продуктах он достаётся тому, кто вышел последним. Канал —
релиз с постоянным тегом и одним файлом, он обновляется на каждом выпуске.

Адрес `releases/latest` остаётся за настольным приложением: сборки 3.0.x и старше вшили его в
бинарный файл и сменить уже не могут. Кто ещё занимает его — в [docs/RELEASES.md](../RELEASES.md).

Профиль программы — `AppData\Roaming\com.foulnike.animori`: `animori-settings.json` (настройки,
пропуск, ключ облака), `animori-snapshot.json`, `animori-dataset.json`. Имя каталога профиля —
`identifier` из конфига; его смена равносильна потере настроек у всех установленных копий.

## Экраны

Имена, меню, заголовки и глубина экрана лежат в `router/routes.ts` отдельно от роутера: по глубине
смена экрана получает направление. Отбор списка в адрес не пишется — закладка, порядок и слово живут
в `lists-keep.ts`, жанр витрины в `home-keep.ts`. Подписи — в `app/labels.ts`.

Десять экранов: главная, списки, статистика, история, поиск, карточка тайтла, студия, плеер,
настройки, журнал. В меню шесть: главная, списки, статистика, история, поиск, настройки; на карточку
и студию попадают из списков, поиска и чипов, на плеер — кнопкой «Смотреть», журнал открывается
адресом `#/log`.

Тема — `styles/theme.css`, единственное место цвета, радиуса, тени, стекла и длительностей. Тем три:
тёмная, светлая, AMOLED; тема живёт атрибутом `data-am-skin` на `<html>`, выбор хранится ключом
`am_appearance`. Акцент живёт дважды: `--am-accent` и `--am-accent-2` — готовые цвета, рядом
`--am-accent-rgb` и `--am-accent-2-rgb` — триплеты для альфы. Акцент — часть темы, рантайм-подмены
цвета нет. Стекло не кладут на списковые строки — сотня `backdrop-filter` за кадр; полоса музыки
исключение, у неё `--am-glass-deep`. `@media (prefers-reduced-motion: reduce)` гасит всё движение.

Шторки поверх экрана (`.am-sheet`, через `Teleport` в `body`): правка записи (`EntrySheet`),
отбор подборки главной (`FilterSheet`). Шторка человека (`PersonSheet`) — инлайн. Панели: `ShotBox`
(кадры и трейлер, через `Teleport`), `PeopleBox` (люди, инлайн), `TuneBox` (темы музыки, через
`Teleport`), `CloudBox` и `ProxyBox` (настройки, инлайн), `PickBox` (ряд выбора значения, из которого
собраны последние две, инлайн). Шторка правит черновик: наружу уходит только «Готово», отдающее все
расшедшиеся поля разом, и на 900 мс становится «Сохранено»; крестик, подложка, Escape и
размонтирование черновик выбрасывают. В подвале у тайтла, который в списке есть, живёт
«Убрать из списка» — она зовёт `editEntry(…, 'remove', …)` и требует двух нажатий, чтобы щелчок рядом
с «Готово» не стоил записи.

Граница разметки и данных: в `.vue` остаётся то, что знает разметка, в `.ts` уезжает то, что знает
данные — `media-card.ts`, `lists-row.ts`, `lists-keep.ts`, `stats-count.ts`, `home-keep.ts`,
`home-spray.ts`, `home-calendar.ts`, `home-activity.ts`.

Журнал отладки — `utils/logger.ts`: запись, буфер и перехватчики. Ловятся `window.error` и
`unhandledrejection` (`logger.ts`, ставятся всегда, а не по флагу), `app.config.errorHandler` и
`warnHandler` Vue ставит `main.ts` — ошибки пошли в журнал сразу после включения. Хвост лежит в
`sessionStorage` под ключом `animori_logs` и переживает перезагрузку страницы. Модуль не импортирует
настройки: иначе `logger → settings → мост` замкнулся бы кольцом и в журнал перестали бы попадать
ровно те слои, где он нужнее всего. Флаг записи в самом журнале (`setLogEnabled`), а значение
приносит главный запуск после чтения настроек. Ошибки Rust и плагинов Tauri в журнал не попадают —
это слепое зрение, и лечится оно только событием Tauri.

## Видео

```
core/video.ts        — виды источников, реестр, pickTrack
api/video-sources.ts — реестр источников: aniliberty, kodik
api/aniliberty.ts    — история просмотра, качество, озвучка, дорожки
api/kodik.ts         — цепочка Kodik, расшифровка адресов
core/playable.ts     — метка доступности, очередь, работники
screens/player-view.ts   — источник, дорожки, качество
screens/player-hls.ts    — hls.js, init, attach, переключение качества
screens/player-cast.ts   — панель системы и локальный экран
screens/player-input.ts  — клавиатура, кнопки, колёса, свайпы
screens/player-keep.ts   — место остановки и история просмотра
PlayerScreen.vue         — путь между плеером и списком
```

Правил у видео три, и все о памяти.

1. **Адрес — только на время показа.** Ссылка на поток и адрес картинки живут в переменных и умирают
   вместе с экраном. В IndexedDB, в снимок, в датасет и в localStorage они не попадают: подпись
   источника сама становится просроченной.
2. **Плеер не сети.** Он ходит только в `player-hls.ts`; сорсировка и выбор дорожки — `api/*` и
   `core/video.ts`.
3. **Ответы метки — на складе.** Метка `PLAY1_` хранится в IndexedDB (медиа-кэш), читается при
   показе плиток без сети; очередь меток спрашивает источники лениво и с придержкой.

Метка доступности `PLAY1_` — один бит: `yes` или `no`, третьего значения нет; её отсутствие означает
«ещё не спрашивали». `yes` ставится от первого источника; `no` — когда высказались все, кому тайтл
адресован; срыв — не ответ. Anilibria в метке не участвует, Kodik — `presenceCost: 'each'`.
Плитки и карточка показывают «Можно посмотреть» только при `yes`. Кнопка «Смотреть» открывает плеер
при любой метке: источники спрашиваются при открытии.

Очередь — тайтлы, порядок — порядок показа; службы идут по дорожке на источник. Пока витрина не
показалась, дорожки молчат: `markFirstPaint()` из `App.vue` даёт секунду после первой отрисовки; без
неё — `BOOT_GRACE_MS` (четыре секунды после пуска). Молчавшие переспрашиваются через `HUSH_TIME_MS`
(десять минут). Потолок очереди — 600 тайтлов. Отказ источника ужимает размер оптового захода
вчетверо и укладывает службу отдохнуть (от 3 до 60 секунд).

Цепочка Kodik: `должно_быть` → страница серии по номеру Шикимори → POST `/ftor` с подписями
`d_sign`/`pd_sign`/`ref_sign` → карта «высота → адреса» → выбор дорожки по высоте окна. Адреса
зашифрованы сдвигом букв и приходят со своим сроком, который пересчитывает `expiryOf`. Один адрес
часто лежит под двумя высотами — на замере 480 и 720 вели на 480.

Готовность на полосе перемотки считается по `el.buffered`: край полосы — конец последнего
подряд загруженного куска, а не длительность ролика.

AniLiberty — отдельный сервис со своим API (`anilibria.top/api/v1`); номер AniList приводится к его
релизу и лежит под `ALIB1_`.

## Устройство репозитория

Ветка одна: `main`. Веток на разработку нет.

| Каталог | Что в нём |
| :--- | :--- |
| `packages/core/src` | Общее ядро: `api`, `core`, `bridge`, `utils` |
| `packages/core/tests` | Наборы общего ядра и заглушка моста |
| `apps/windows` | Настольное приложение |
| `apps/android-tv` | Приложение для телевизора |
| `apps/android` | Приложение для телефона |
| `docs` | Документация: правовая в корне, инженерная в `docs/dev/` |
| `.github/workflows` | Сторож датасета, проверки, все выпуски |

Сборка и проверки:

```bash
npm ci                                      # корень
npm test                                    # ядро, потом все приложения
npm run typecheck                           # все приложения
npm run build:windows
npm run build:android-tv
npm run build:android
```

Разработка идёт из каталога приложения:

```bash
cd apps/windows && npm run tauri dev
cd apps/android-tv && npm run tauri -- android dev
cd apps/android && npm run tauri -- android dev
```

### Выпуски

| Продукт | Тег | Что собирается |
| :--- | :--- | :--- |
| Настольное | `windows-v<версия>` | NSIS, MSI, портативный архив |
| Телевизор | `android-tv-v<версия>` | `armv7` и `arm64` |
| Телефон | `android-v<версия>` | `arm64` и `armv7` |

Номер в теге сверяется с `package.json` приложения; расхождение роняет прогон. Файлы приставки и
телефона называются `AniMori_<версия>_<разрядность>.apk`; разрядность приложение выбирает по своёй.

Канал обновлений Windows — релиз `windows-latest`. Он помечен предварительным: иначе занимал бы
метку «последний выпуск» и ломал ручные ссылки на установщик. Конвейер создаёт его заново на каждом
выпуске и проверяет адрес, который читает апдейтер. Кто ещё занимает `releases/latest` и почему так
— в [docs/RELEASES.md](../RELEASES.md).

### Грабли

Папки сборки в `src-tauri/target` переживают перемещение каталогов и хранят старые абсолютные пути.
После переезда cargo не перезапускает скрипт и падает на чтении файла, которого нет. Лечится
удалением `src-tauri/target/debug/build`:

```powershell
Get-ChildItem apps/windows/src-tauri/target/debug/build -Directory |
  Remove-Item -Recurse -Force
```

Полная чистка `src-tauri/target` помогает тоже, но это пересборка всех зависимостей заново.
